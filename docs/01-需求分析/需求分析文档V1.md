## 1. 引言

### 1.1 编写目的

本文档旨在明确"智聘星图"系统的功能需求、非功能需求以及系统边界，为后续的设计、开发和测试工作提供依据。本文档面向项目团队全体成员。

### 1.2 项目背景

随着人工智能技术的快速发展，传统招聘行业面临简历筛选效率低、人岗匹配不精准、人才评估维度单一等痛点。本系统基于银河麒麟操作系统，利用大模型、自然语言处理和知识图谱技术，构建一个智能化的招聘匹配与能力图谱平台，实现简历与岗位的智能解析、能力可视化与人岗精准匹配。

### 1.3 适用范围

本文档适用于智聘星图系统的需求分析阶段，涵盖系统所有功能模块的定义与说明。

---

## 2. 项目背景

### 2.1 行业现状

- 传统招聘平台简历量大，人工筛选耗时耗力
- 岗位描述与简历技能难以结构化对比
- 求职者缺乏清晰的职业发展方向
- 企业难以批量评估候选人能力匹配度

### 2.2 解决方案

本系统通过以下方式解决上述问题：
1. **AI文档解析**：自动解析PDF/DOC/DOCX格式简历和岗位JD，提取结构化信息
2. **能力图谱**：基于技能提取结果，生成可视化的个人/岗位能力图谱
3. **智能匹配**：基于多维度评分算法，实现精准的人岗推荐
4. **职业规划**：分析技能缺口，推荐学习路径和职业发展方向

---

## 3. 建设目标

- 构建一个完整的求职招聘智能匹配平台
- 支持求职者端、企业端和管理端三端分离
- 实现简历/岗位文档的AI自动解析与结构化提取
- 生成可视化的个人能力图谱与岗位能力图谱
- 提供基于多维度评分的人岗智能推荐
- 提供AI驱动的职业规划建议
- 部署于银河麒麟高级服务器操作系统（LoongArch架构）

---

## 4. 可行性分析

### 4.1 技术可行性

| 维度 | 说明 |
|------|------|
| 开发语言 | Java 21（后端主服务）、Python 3.12（AI服务）、TypeScript/Vue 3（前端） |
| 运行环境 | 银河麒麟V10/V11，LoongArch架构CPU |
| 数据库 | 人大金仓KingbaseES，原生支持龙芯+麒麟 |
| AI能力 | 通过API调用大模型（DeepSeek等），结合sentence-transformers做语义嵌入 |
| 文档解析 | docling/pdfplumber/python-docx支持主流文档格式 |

### 4.2 经济可行性

项目使用开源技术栈，无额外商业授权费用。大模型API调用成本可控。

### 4.3 操作可行性

系统采用B/S架构，用户通过浏览器访问，操作简便。管理端提供数据统计和系统监控功能。

## 5. 用户需求分析

### 5.1 用户角色

| 角色 | 描述 |
|------|------|
| 求职者（USER） | 浏览岗位、上传简历、查看能力图谱、获取推荐和职业规划 |
| 企业用户（COMPANY） | 发布岗位、查看人才推荐、管理候选人 |
| 系统管理员（ADMIN） | 用户管理、企业管理、数据统计、系统监控 |

### 5.2 用户场景

**场景一：求职者使用流程**
1. 用户注册/登录
2. 上传个人简历（PDF/DOC/DOCX）
3. 系统自动解析简历，提取技能、经历等信息
4. 生成个人能力图谱（雷达图/关系图）
5. 获取AI推荐的匹配岗位列表
6. 查看职业规划建议

**场景二：企业使用流程**
1. 企业注册/登录
2. 上传岗位JD文档
3. 系统自动解析岗位需求，提取技能要求
4. 生成岗位能力图谱
5. 获取AI推荐的人才列表
6. 查看候选人与岗位的匹配详情

**场景三：管理员使用流程**
1. 管理员登录
2. 管理平台用户和企业的账号
3. 查看系统数据统计报表
4. 监控系统运行状态

### 6.8 职业规划中心

## 7. 非功能需求

### 7.1 性能需求

| 指标 | 要求 |
|------|------|
| 页面响应时间 | ≤ 2秒 |
| API响应时间 | ≤ 500ms（不含AI解析） |
| AI文档解析时间 | ≤ 30秒/份 |
| 并发用户数 | 支持 ≥ 100人同时在线 |

### 7.2 安全性需求

- 密码加密存储（BCrypt）
- 基于JWT的Token认证
- 接口权限校验
- 文件上传类型和大小限制

### 7.3 可用性需求

- 系统7×24小时稳定运行
- 界面简洁清晰，符合用户操作习惯
- 关键操作有确认提示和错误反馈

### 7.4 兼容性需求

- 前端兼容主流浏览器（Chrome、Firefox、Edge）
- 后端部署于银河麒麟V10/V11（LoongArch架构）
- 数据库使用人大金仓KingbaseES
